Tracing & Metrics

Observe every request in real time through the live trace stream. Monitor performance and error rates with per-spec and per-operation statistics, and expose Prometheus metrics for external monitoring.

Request Tracing

go-virtual captures a complete trace record for every request it handles. Traces include:

  • Full request details — method, URL, headers, body
  • Response details — status code, headers, body, latency
  • Which response configuration matched (or "no match")
  • Script execution details — output, logs, execution time, errors
  • Session information — session ID and store operations performed
  • Timestamps for each pipeline stage

Traces are stored in a configurable ring buffer (default: 1000 traces) and can be streamed over WebSocket for real-time monitoring.

Enabling/disabling tracing per spec

# Disable tracing for a noisy spec
curl -X PUT http://localhost:8080/_api/specs/spec_id/tracing \
  -H "Content-Type: application/json" \
  -d '{"enabled": false}'

# Re-enable
curl -X PUT http://localhost:8080/_api/specs/spec_id/tracing \
  -d '{"enabled": true}'

Trace Schema

Each trace record has the following structure:

{
  "id": "trace_abc123",
  "timestamp": "2024-01-15T10:00:00.123Z",
  "specId": "spec_xyz",
  "operationId": "op_123",
  "operationName": "getPet",

  "request": {
    "method": "GET",
    "url": "/pets/42",
    "headers": { "Authorization": "Bearer ..." },
    "body": ""
  },

  "response": {
    "statusCode": 200,
    "headers": { "Content-Type": "application/json" },
    "body": "{\"id\":\"42\",\"name\":\"Max\"}",
    "latencyMs": 12
  },

  "matchedResponse": {
    "id": "resp_456",
    "name": "Success"
  },

  "scripts": [
    {
      "scriptId": "script_789",
      "outputKey": "info",
      "output": { "greeting": "Hello" },
      "logs": ["Processing request for 42"],
      "executionMs": 3,
      "error": ""
    }
  ],

  "session": {
    "id": "user-alice-1",
    "storeReads": ["cart"],
    "storeWrites": ["cart"]
  }
}

WebSocket Live Stream

Connect to the trace stream WebSocket endpoint to receive trace events in real time as requests arrive:

# Using wscat or websocat
wscat -c ws://localhost:8080/_api/traces/stream

# Using websocat
websocat ws://localhost:8080/_api/traces/stream

Each message received is a full trace record serialized as JSON, followed by a newline.

Filter by spec

wscat -c "ws://localhost:8080/_api/traces/stream?specId=spec_xyz"

Using the trace stream from JavaScript

const ws = new WebSocket('ws://localhost:8080/_api/traces/stream')

ws.onmessage = (event) => {
    const trace = JSON.parse(event.data)
    console.log(`[${trace.response.statusCode}] ${trace.request.method} ${trace.request.url} — ${trace.response.latencyMs}ms`)
}

ws.onerror = console.error

Admin UI Trace Viewer

The Traces page in the admin UI provides a live feed of trace events with:

  • Auto-scroll as new traces arrive
  • Full-text search across all trace fields
  • Filter by spec or operation
  • Click to expand trace details (request/response body, script output)
  • JSON syntax highlighting
  • Clear all traces button

Trace API

List traces (paginated)

# List recent traces
curl "http://localhost:8080/_api/traces?limit=50&offset=0"

# Filter by spec
curl "http://localhost:8080/_api/traces?specId=spec_xyz"

# Filter by operation
curl "http://localhost:8080/_api/traces?operationId=op_abc"

# Search full text
curl "http://localhost:8080/_api/traces?q=error"

Get a single trace

curl http://localhost:8080/_api/traces/trace_abc123

Clear all traces

curl -X DELETE http://localhost:8080/_api/traces

Tracing Configuration

tracing:
  maxTraces: 1000     # Maximum trace records to keep in memory
  retention: "24h"   # Time to retain traces
OptionDefaultDescription
maxTraces1000Ring buffer size. When full, oldest traces are evicted.
retention24hMaximum age of a trace before it's removed regardless of buffer size.
💡
High-traffic environments In high-traffic environments, reduce maxTraces or disable tracing for noisy specs to limit memory usage. Trace bodies are not compressed.

Statistics

go-virtual tracks request counts, response times, and error rates at three levels: global, per-spec, and per-operation.

Global statistics

curl http://localhost:8080/_api/stats

# Response
{
  "totalRequests": 1523,
  "totalErrors": 42,
  "averageLatencyMs": 18.4,
  "p99LatencyMs": 120,
  "activeSpecs": 3,
  "uptime": "2h15m"
}

Per-spec statistics

curl http://localhost:8080/_api/stats/specs/spec_xyz

{
  "specId": "spec_xyz",
  "totalRequests": 850,
  "errorRate": 0.02,
  "averageLatencyMs": 14.2
}

Per-operation statistics

curl http://localhost:8080/_api/stats/operations/op_abc

{
  "operationId": "op_abc",
  "operationName": "getPet",
  "totalRequests": 320,
  "successCount": 310,
  "errorCount": 10,
  "averageLatencyMs": 11.8
}

Reset statistics

curl -X POST http://localhost:8080/_api/stats/reset

Admin UI Dashboard

The Dashboard page visualizes statistics with:

  • Total request count and error rate gauges
  • Average and P99 latency charts over time
  • Top operations by request volume
  • Per-spec breakdown table
  • Real-time trend lines (updates as requests arrive)

Prometheus Metrics

go-virtual exposes Prometheus-compatible metrics at /_prometheus.

curl http://localhost:8080/_prometheus

# HELP go_virtual_requests_total Total number of requests handled
# TYPE go_virtual_requests_total counter
go_virtual_requests_total{spec="pet-store",operation="getPet",status="200"} 320
go_virtual_requests_total{spec="pet-store",operation="listPets",status="200"} 150

# HELP go_virtual_latency_seconds Request latency in seconds
# TYPE go_virtual_latency_seconds histogram
go_virtual_latency_seconds_bucket{le="0.01"} 280
...

# HELP go_virtual_active_specs Number of enabled specs
# TYPE go_virtual_active_specs gauge
go_virtual_active_specs 3

Prometheus scrape config

# prometheus.yml
scrape_configs:
  - job_name: "go-virtual"
    static_configs:
      - targets: ["localhost:8080"]
    metrics_path: "/_prometheus"
    scrape_interval: 15s
