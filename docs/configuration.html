Overview

go-virtual uses a YAML configuration file (default: ./config.yaml). You can specify a different path with the --config flag:

go-virtual serve --config /etc/go-virtual/config.yaml

Run go-virtual init to generate a default config.yaml in the current directory.

💡
CLI flags override config CLI flags (like --port and --tls) take precedence over values in config.yaml. Environment variables also override config file values.

server

HTTP server settings.

server:
  port: 8080          # TCP port to listen on
  host: "0.0.0.0"    # Bind address ("0.0.0.0" = all interfaces)
KeyTypeDefaultDescription
server.portinteger8080TCP port number. Can be overridden with --port flag.
server.hoststring"0.0.0.0"Bind address. Use "127.0.0.1" to listen only on loopback.

server.tls

TLS/HTTPS configuration. go-virtual supports both manually provided certificates and auto-generated self-signed certificates.

server:
  tls:
    enabled: false           # Enable HTTPS
    certFile: ""             # Path to PEM certificate file
    keyFile: ""              # Path to PEM private key file
    autoGenerate: true       # Auto-generate self-signed cert if none provided
    storePath: ""            # Where to store the auto-generated cert (default: data/certs/)
KeyTypeDefaultDescription
tls.enabledboolfalseEnable TLS. Can be overridden with --tls flag.
tls.certFilestring""Path to PEM certificate. If empty and autoGenerate is true, a self-signed cert is generated.
tls.keyFilestring""Path to PEM private key. Must be paired with certFile.
tls.autoGeneratebooltrueGenerate a self-signed certificate if no cert files are provided.
tls.storePathstring"data/certs"Directory where auto-generated certificates are saved between restarts.

Both HTTP and HTTPS

go-virtual uses TLS multiplexing (BoringSSL-style sniffing) to serve both HTTP and HTTPS on the same port simultaneously. Clients that don't initiate a TLS handshake receive plain HTTP.

Production TLS setup

server:
  port: 443
  tls:
    enabled: true
    certFile: /etc/letsencrypt/live/example.com/fullchain.pem
    keyFile: /etc/letsencrypt/live/example.com/privkey.pem
    autoGenerate: false

storage

Configure where go-virtual persists its data.

storage:
  type: "file"         # "file" or "memory"
  path: "./data"      # Base directory (only used with type: file)
KeyTypeDefaultDescription
storage.typestring"file""file" for persistent JSON storage, "memory" for ephemeral in-memory storage.
storage.pathstring"./data"Root directory for file storage. Created automatically if it doesn't exist.

File storage

All data is stored as atomic JSON files in subdirectories of storage.path. Writes use a two-file pattern (write to .tmp, then rename) for crash safety.

In-memory storage

Nothing is persisted to disk. All specs, responses, scripts, traces, and session data are lost on restart. Useful for:

  • Stateless container deployments
  • CI/CD test environments
  • Local development without cluttering the working directory
storage:
  type: "memory"

tracing

tracing:
  maxTraces: 1000       # Ring buffer size
  retention: "24h"     # Maximum trace age before eviction
KeyTypeDefaultDescription
tracing.maxTracesinteger1000Maximum number of trace records kept in memory. Oldest entries are evicted when full.
tracing.retentionduration"24h"How long to keep trace records. Format: 1h, 30m, 72h, etc.

logging

logging:
  level: "info"         # debug, info, warn, error
  format: "json"       # "json" or "text"
KeyTypeDefaultDescription
logging.levelstring"info"Log verbosity. Use "debug" to see all request routing decisions and script executions.
logging.formatstring"json""json" for structured logging (recommended for production/log aggregation), "text" for human-readable output.

scripting

scripting:
  defaultTimeoutMs: 100   # Default script execution timeout (ms)
KeyTypeDefaultDescription
scripting.defaultTimeoutMsinteger100Default timeout applied to scripts that don't specify their own timeoutMs. Minimum is 1ms, maximum is 10000ms (10 seconds).
⚠️
Timeout applies to all requests The script timeout adds to the overall request latency. Keep scripts fast (under 10ms) for best performance. The sleep() builtin is capped at the timeout value.

session

session:
  headerName: "X-Virtual-Session-Id"  # Request header for session ID
  inactivityTimeout: "30m"          # Session expiry after inactivity
  maxSessions: 10000                # Max concurrent active sessions
KeyTypeDefaultDescription
session.headerNamestring"X-Virtual-Session-Id"HTTP header that clients use to identify their session.
session.inactivityTimeoutduration"30m"A session is deleted if no request uses it for this duration. Resets on each request.
session.maxSessionsinteger10000Maximum concurrent sessions. New sessions are rejected when this limit is reached until existing sessions expire.

proxy

Settings for when go-virtual forwards requests to a real backend (proxy mode).

proxy:
  timeoutSeconds: 30             # Backend request timeout
  insecureSkipVerify: false      # Skip TLS cert verification for backends
  mtls:
    certFile: ""                  # Client certificate for mTLS backends
    keyFile: ""                   # Client private key
    caCertFile: ""               # CA cert to verify backend's certificate
KeyTypeDefaultDescription
proxy.timeoutSecondsinteger30Maximum time to wait for a backend response before failing with a 504.
proxy.insecureSkipVerifyboolfalseSkip TLS certificate verification for backend HTTPS connections. Not recommended for production.
proxy.mtls.certFilestring""Path to client certificate for mTLS authentication with the backend.
proxy.mtls.keyFilestring""Path to client private key for mTLS.
proxy.mtls.caCertFilestring""Path to CA certificate used to verify the backend server's TLS certificate.

mTLS proxy example

proxy:
  timeoutSeconds: 60
  mtls:
    certFile: /certs/client.crt
    keyFile: /certs/client.key
    caCertFile: /certs/ca-bundle.crt

branding

Customize the Admin UI title and subtitle for multi-tenant or white-label deployments.

branding:
  appTitle: ""          # Custom name shown in the UI header
  appSubtitle: ""      # Custom tagline shown below the title
KeyTypeDefaultDescription
branding.appTitlestring"go-virtual"Application name displayed in the UI header and browser tab.
branding.appSubtitlestring"API Mock & Virtualization"Subtitle shown below the title in the Admin UI.

Full Example

A complete config.yaml with all options:

# go-virtual configuration

server:
  port: 8080
  host: "0.0.0.0"
  tls:
    enabled: false
    certFile: ""
    keyFile: ""
    autoGenerate: true
    storePath: ""

storage:
  type: "file"
  path: "./data"

tracing:
  maxTraces: 1000
  retention: "24h"

logging:
  level: "info"
  format: "json"

scripting:
  defaultTimeoutMs: 100

session:
  headerName: "X-Virtual-Session-Id"
  inactivityTimeout: "30m"
  maxSessions: 10000

proxy:
  timeoutSeconds: 30
  insecureSkipVerify: false
  mtls:
    certFile: ""
    keyFile: ""
    caCertFile: ""

branding:
  appTitle: ""
  appSubtitle: ""

Environment Variables

All config values can be overridden with environment variables. The naming convention is: uppercase the key path and replace dots with underscores, prefixed with GV_:

Environment VariableConfig key
GV_SERVER_PORTserver.port
GV_SERVER_HOSTserver.host
GV_SERVER_TLS_ENABLEDserver.tls.enabled
GV_SERVER_TLS_CERTFILEserver.tls.certFile
GV_SERVER_TLS_KEYFILEserver.tls.keyFile
GV_STORAGE_TYPEstorage.type
GV_STORAGE_PATHstorage.path
GV_LOGGING_LEVELlogging.level
GV_LOGGING_FORMATlogging.format
GV_SESSION_HEADERNAMEsession.headerName
GV_SESSION_INACTIVITYTIMEOUTsession.inactivityTimeout
GV_PROXY_TIMEOUTSECONDSproxy.timeoutSeconds
 
# Run with custom port and in-memory storage
GV_SERVER_PORT=3000 GV_STORAGE_TYPE=memory go-virtual serve

Config Precedence

Configuration values are resolved in this order (highest priority first):

  1. CLI flags — --port 3000, --tls, etc.
  2. Environment variables — GV_SERVER_PORT=3000
  3. config.yaml — Values in the configuration file
  4. Built-in defaults — Hardcoded defaults as shown in this reference
# Port 3000 wins over the 8080 in config.yaml
go-virtual serve --port 3000 --config config.yaml
💡
Combining config file and environment Use the config file for static settings (storage, TLS certs) and environment variables for runtime overrides (port, log level, feature toggles). This pattern works well with container deployments.
