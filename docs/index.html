API Mock & Virtualization
for OpenAPI 3

go-virtual is a self-hosted OpenAPI 3 virtualization service with three execution modes — standard, AI, and proxy — plus dynamic responses, Starlark scripting, session state, and real-time tracing.

→ Get Started 🖥️ Admin UI Guide 🔀 Modes & Recording API Reference

What is go-virtual?

go-virtual sits in front of your services and serves mock responses based on OpenAPI 3 specifications. It is designed for:

  • Frontend development — Mock backend APIs without running real services
  • Integration testing — Simulate edge cases, errors, and latency
  • API contract validation — Ensure clients respect the spec
  • Demos & staging environments — Serve predictable, configurable data
  • Traffic recording — Proxy live traffic and replay captured responses later
  • Runtime AI generation — Generate structured responses from the request and OpenAPI response schema

How It Works

Every inbound HTTP request passes through a pipeline:

  1. Route Matching — The request path and method are matched against all enabled OpenAPI operations across uploaded specs.

  2. Request Signature — The request is fingerprinted using the operation’s signature configuration so recorded/generated responses can be replayed precisely.

  3. Condition Evaluation — Saved response configurations are evaluated in priority order. The first config whose conditions match is selected.

  4. Mode Fallback — If no saved response matches, the spec falls back according to its mode: OpenAPI example/default, runtime AI generation, or upstream proxy.

  5. Response, Recording & Tracing — The final response is sent to the client, optionally recorded for replay, and captured with mode/source-aware trace metadata.

Quick Start (60 seconds)

1. Install

# Using Go toolchain
go install github.com/prasenjit-net/go-virtual@latest

# Or build from source
git clone https://github.com/prasenjit-net/go-virtual.git
make build

2. Initialize a workspace

go-virtual init
# Creates config.yaml and data/ directory

3. Start the server

go-virtual serve
# Server listening on http://localhost:8080
# Admin UI at http://localhost:8080/_ui/

4. Upload an OpenAPI spec

curl -X POST http://localhost:8080/_api/specs \
  -H "Content-Type: application/json" \
  -d '{"name": "Pets API", "content": "openapi: \"3.0.0\"\ninfo:\n  title: Pets\n  version: 1.0.0\npaths:\n  /pets/{id}:\n    get:\n      operationId: getPet\n      parameters:\n        - name: id\n          in: path\n          required: true\n          schema:\n            type: string\n      responses:\n        \"200\":\n          description: OK"}'

5. Create a mock response

# First get the operation ID
curl http://localhost:8080/_api/specs/<spec-id>/operations

# Create a response config
curl -X POST http://localhost:8080/_api/operations/<op-id>/responses \
  -H "Content-Type: application/json" \
  -d '{"name": "Success", "statusCode": 200, "priority": 0,
     "body": "{\"id\": \"{{path.id}}\", \"name\": \"{{faker.name.first}} {{faker.name.last}}\"}"}'

6. Test it

curl http://localhost:8080/pets/42
# {"id":"42","name":"James Anderson"}
💡
Admin UI You can do all of the above (and more) through the visual admin interface at http://localhost:8080/_ui/. No curl required.

Project Status

go-virtual is actively developed. The current feature set includes spec modes, recorded/generated response management, Starlark scripting, session-aware store, tracing, archives, and an embedded admin UI. See the GitHub repository for releases.
