go-virtual / Starlark Scripting

Starlark Scripting

Write sandboxed Python-like scripts that execute per-request to compute dynamic values, maintain state counters, hash data, parse JSON, and produce named outputs consumed by the template engine.

Overview

Scripts in go-virtual use Starlark, a dialect of Python designed for configuration and scripting. It's deterministic, sandboxed, and has no access to the filesystem, network, or OS.

  • Scripts are attached to operations via bindings
  • Each request triggers the bound script before response selection
  • Scripts return a dictionary whose fields become template variables
  • Script compilation is cached for performance (keyed by script ID + updatedAt)
  • Default execution timeout is 100ms (configurable)
💡
When to use scripts Use scripts when you need logic that can't be expressed with template variables alone: calculations, hashing, conditionals, counter-based state, or calling into the session store.

Writing Scripts

Every script must define a run(req) function that accepts the request context and returns a dictionary (or None).

def run(req):
    # req is a dict with path, query, header, body fields
    user_id = req["path"].get("id", "unknown")

    return {
        "greeting": "Hello, user " + user_id,
        "requestedAt": now("iso")
    }

Creating a script via API

curl -X POST http://localhost:8080/_api/scripts \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Order Calculator",
    "source": "def run(req):\n  qty = req[\"body\"].get(\"quantity\", 0)\n  price = req[\"body\"].get(\"unitPrice\", 0)\n  return {\"total\": qty * price, \"currency\": \"USD\"}",
    "timeoutMs": 100
  }'

Request Context

The req dictionary passed to run() contains all request data:

req = {
    "path":   { "id": "42", ... },          # URL path parameters
    "query":  { "page": "1", ... },         # Query string parameters
    "header": { "Authorization": "..." },  # HTTP headers (lowercased keys)
    "body":   { "user": { ... } }           # Parsed JSON body (dict/list)
}

Accessing request data

def run(req):
    # Safe access with .get() and default values
    page = req["query"].get("page", "1")
    per_page = req["query"].get("per_page", "20")

    auth = req["header"].get("authorization", "")
    is_admin = auth.startswith("Bearer admin-")

    user_name = req["body"].get("name", "anonymous")

    return {
        "page": int(page),
        "isAdmin": is_admin,
        "user": user_name
    }
⚠️
Body may be None If the request has no JSON body (e.g., a GET request), req["body"] will be an empty dict. Always use .get(key, default) to avoid key errors.

Script Bindings

A binding associates a script with an operation. When the operation is called, the bound scripts execute in binding order. Each binding has an outputKey — the name used to reference that script's output in templates.

Create a binding

curl -X POST http://localhost:8080/_api/operations/<op-id>/scripts \
  -H "Content-Type: application/json" \
  -d '{
    "scriptId": "<script-id>",
    "outputKey": "pricing"
  }'

Multiple scripts per operation

You can bind multiple scripts to a single operation. Each must have a unique outputKey. All scripts execute in order, and all their outputs are available in templates:

# Bind a pricing script
{ "scriptId": "script-price-id", "outputKey": "pricing" }

# Bind an audit script
{ "scriptId": "script-audit-id", "outputKey": "audit" }

# Template can use both
{ "total": {{.script.pricing.total}}, "requestId": "{{.script.audit.requestId}}" }

List and remove bindings

# List bindings for an operation
curl http://localhost:8080/_api/operations/<op-id>/scripts

# Remove a binding
curl -X DELETE http://localhost:8080/_api/operations/<op-id>/scripts/<binding-id>

Using Script Output in Templates

Script output is available in response body and header templates under {{.script.<outputKey>.<field>}}:

// Script with outputKey = "order" returns: {"total": 99.95, "items": 3, "currency": "USD"}

// Response body template:
{
  "orderId": "{{random.uuid}}",
  "total": {{.script.order.total}},
  "itemCount": {{.script.order.items}},
  "currency": "{{.script.order.currency}}"
}

Standard Builtins

go-virtual injects 14 built-in functions into every script's global scope:

uuid()
Generate a UUID v4 string.
id = uuid()
# "f47ac10b-58cc-4372-a567-..."
now(format)
Current timestamp. Format: "unix", "unix_ms", "iso", "date".
ts = now("iso")
# "2024-01-15T10:00:00Z"
rand_int(min, max)
Random integer between min and max (inclusive).
score = rand_int(0, 100)
rand_choice(list)
Pick a random element from a list.
status = rand_choice(["active", "pending", "closed"])
counter(name, delta)
Atomic persistent counter. name is the counter key, delta is the increment (can be negative). Returns new value. Session-scoped by default.
n = counter("requests", 1)
base64_encode(str)
Base64-encode a string.
encoded = base64_encode("hello world")
# "aGVsbG8gd29ybGQ="
base64_decode(str)
Decode a base64 string.
plain = base64_decode("aGVsbG8=")
# "hello"
hash(algo, str)
Cryptographic hash. Algorithms: "md5", "sha1", "sha256", "sha512". Returns hex string.
h = hash("sha256", "hello")
# "2cf24dba5fb0a..."
json_parse(str)
Parse a JSON string into a Starlark dict/list.
obj = json_parse('{"key": 1}')
val = obj["key"]  # 1
json_stringify(obj)
Serialize a Starlark dict/list to a JSON string.
s = json_stringify({"a": 1})
# '{"a":1}'
sleep(ms)
Pause execution for ms milliseconds. Capped at the script timeout.
sleep(50)  # wait 50ms
regex_match(pattern, str)
Returns True if the entire string matches the pattern.
ok = regex_match(r"\d+", "123")
# True
regex_find(pattern, str)
Returns the first match substring, or empty string.
m = regex_find(r"\d+", "abc123")
# "123"
log(msg, ...)
Emit a log message visible in trace details and the server log.
log("Processing request for", user_id)

Store Builtin

Scripts have access to a store object that provides per-session key-value storage. See Sessions & Store for full details.

def run(req):
    # Read a value from the session store
    cart_json = store.get("cart")
    cart = json_parse(cart_json) if cart_json else []

    # Add item to cart
    item = req["body"].get("item")
    if item:
        cart.append(item)
        store.set("cart", json_stringify(cart))

    return { "cartSize": len(cart) }
MethodDescription
store.get(key)Read a value by key. Returns the value or None.
store.set(key, value)Write a value by key.
store.delete(key)Remove a key.
store.keys()List all keys in the current session store.

Script Lifecycle

  1. Compilation — On first execution, the Starlark source is compiled and cached (keyed by script ID + updatedAt timestamp). Subsequent requests use the cached bytecode.

  2. Execution — A goroutine runs the script with a deadline equal to timeoutMs. The run(req) function is called with the request context.

  3. Output capture — The return value of run() is converted to a Go map and stored under the binding's outputKey.

  4. Template rendering — The response body/headers template is rendered with all script outputs available.

  5. Error handling — If the script panics, times out, or throws an error, execution falls through gracefully. The script output is empty but the response still renders.

⚠️
Step limits Starlark enforces a maximum step count to prevent infinite loops. Scripts that try to compute indefinitely will be terminated before reaching the timeout.

Testing Scripts

You can validate and test scripts before binding them to operations:

Validate syntax

curl -X POST http://localhost:8080/_api/scripts/validate \
  -H "Content-Type: application/json" \
  -d '{
    "source": "def run(req):\n  return {\"ok\": True}"
  }'
# {"valid": true}

Test with mock input

curl -X POST http://localhost:8080/_api/scripts/<script-id>/test \
  -H "Content-Type: application/json" \
  -d '{
    "req": {
      "path": {"id": "42"},
      "query": {"debug": "true"},
      "header": {"authorization": "Bearer test"},
      "body": {"quantity": 3, "unitPrice": 29.99}
    }
  }'

# Response:
{
  "output": { "total": 89.97, "currency": "USD" },
  "logs": [],
  "executionMs": 2
}

Admin UI test panel

The Scripts page in the Admin UI has a built-in test panel where you can fill in mock request fields and run the script interactively, seeing output and logs in real time.

Security & Sandboxing

Starlark is designed for safe, sandboxed execution:

  • No file system access — Scripts cannot read or write files
  • No network access — Scripts cannot make HTTP requests or open sockets
  • No OS access — No exec, system, or environment variables
  • No imports — The standard Starlark library modules are not available (only go-virtual builtins)
  • Step limits — A maximum step budget prevents infinite loops
  • Timeout — A goroutine deadline hard-terminates runaway scripts
  • Panic recovery — Script panics are caught and don't crash the server
🔒
Safe to run untrusted scripts go-virtual's Starlark sandbox makes it safe to run scripts from less-trusted team members without risk of server compromise.

Examples

Order total calculator

def run(req):
    body = req["body"]
    items = body.get("items", [])

    subtotal = 0
    for item in items:
        subtotal += item.get("price", 0) * item.get("qty", 1)

    tax = subtotal * 0.08
    total = subtotal + tax

    log("Order total:", total)

    return {
        "subtotal": subtotal,
        "tax": tax,
        "total": total,
        "itemCount": len(items),
        "orderId": uuid()
    }

Request signature / fingerprint

def run(req):
    # Create a unique fingerprint for this request
    user_id = req["path"].get("id", "")
    ts = now("unix")
    raw = user_id + ":" + str(ts)

    return {
        "signature": hash("sha256", raw),
        "nonce": base64_encode(uuid())
    }

Rate limiter simulation

def run(req):
    user_id = req["path"].get("id", "anonymous")
    key = "ratelimit:" + user_id

    # Increment request counter
    count = counter(key, 1)
    limit = 10
    remaining = limit - count

    return {
        "requestCount": count,
        "remaining": remaining if remaining > 0 else 0,
        "exceeded": count > limit
    }

JWT-like token decoder (base64)

def run(req):
    auth = req["header"].get("authorization", "")
    if not auth.startswith("Bearer "):
        return {"valid": False}

    token = auth[7:]  # strip "Bearer "
    parts = token.split(".")
    if len(parts) != 3:
        return {"valid": False}

    # Decode the payload section
    payload_raw = base64_decode(parts[1])
    payload = json_parse(payload_raw)

    return {
        "valid": True,
        "subject": payload.get("sub", ""),
        "role": payload.get("role", "user")
    }

Random but realistic response

def run(req):
    statuses = ["active", "inactive", "pending", "suspended"]
    tiers = ["free", "pro", "enterprise"]

    return {
        "status": rand_choice(statuses),
        "tier": rand_choice(tiers),
        "score": rand_int(0, 1000),
        "generatedAt": now("iso")
    }
