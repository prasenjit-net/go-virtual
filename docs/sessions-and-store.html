Sessions & Store

Maintain stateful data across requests using per-client sessions and a persistent global key-value store. Scripts can read and write session data; admins manage the global store.

Concepts

go-virtual has two layers of state storage:

🌐
Global Store
Application-wide persistent key-value store. Managed by admins. Acts as the seed data for new sessions. Scripts cannot directly modify it (read-only from scripts).
👤
Sessions
Per-client ephemeral store. Created automatically on first request with a session ID. Scripts can freely read and write. Expires after inactivity.

When a new session is created, it receives a deep copy of the global store. Subsequent writes by scripts only affect the session copy, not the global store.

Global Store

The global store is a flat key-value map where keys and values are strings. It is persisted to data/store.json and survives server restarts.

Setting global values

# Set a value
curl -X PUT http://localhost:8080/_api/store/config.featureFlags \
  -H "Content-Type: application/json" \
  -d '{"value": "{\"betaMode\": true, \"maxItems\": 50}"}'

# Set another value
curl -X PUT http://localhost:8080/_api/store/defaultCurrency \
  -H "Content-Type: application/json" \
  -d '{"value": "USD"}'

Reading global values

curl http://localhost:8080/_api/store/defaultCurrency
# {"key": "defaultCurrency", "value": "USD"}

# List all keys
curl http://localhost:8080/_api/store
# {"items": [{"key": "defaultCurrency", "value": "USD"}, ...]}

Deleting global values

# Delete a single key
curl -X DELETE http://localhost:8080/_api/store/defaultCurrency

# Clear entire global store (requires confirmation)
curl -X DELETE "http://localhost:8080/_api/store?confirm=true"
⚠️
Scripts cannot write to the global store The store builtin in scripts is session-scoped. Admin API calls are the only way to modify global store values. This prevents script bugs from corrupting shared state.

Sessions

Sessions are automatically created for clients that include an X-Virtual-Session-Id header (configurable). A session is a private key-value store initialized with a snapshot of the global store.

Session lifecycle

  1. First request with session header — go-virtual looks up the session ID. If no session exists, one is created with a deep copy of the global store.

  2. Script execution — The bound script's store object is scoped to this session. Reads and writes affect only this session's copy.

  3. Response — The session ID is echoed back in the response header, confirming the session was used.

  4. Inactivity expiry — If no request is made with this session ID for the configured inactivity timeout (default 30 minutes), the session is cleaned up.

Session Header

The default session header is X-Virtual-Session-Id. You can configure a different name in config.yaml.

# Client sends a session ID (can be any string)
curl http://localhost:8080/api/cart \
  -H "X-Virtual-Session-Id: user-alice-session-1"

# Server echoes it back in the response
# X-Virtual-Session-Id: user-alice-session-1
💡
Choose any session ID The session ID is just a string key. Use whatever is convenient — a UUID, a user ID, a test name. Different IDs get different isolated session stores.

Request without a session header

If a request arrives without a session header, scripts still run but the store object operates on an ephemeral in-memory store that is discarded after the request. No session record is persisted.

Deep Copy Semantics

When a session is first created, it receives a deep copy of the entire global store at that moment. This means:

  • Sessions start with any seed data you put in the global store
  • Changes to the global store after session creation do not affect existing sessions
  • Two sessions are completely isolated — one session's writes don't affect another
  • You can reset a session by deleting it; the next request creates a fresh copy from global store

Use case: Seeding test data

# Put initial catalog into global store
curl -X PUT http://localhost:8080/_api/store/products \
  -d '{"value": "[{\"id\":\"p1\",\"name\":\"Widget\",\"price\":9.99}]"}'

# Each new session starts with this product catalog
# Tests can add/remove products within their session without affecting others

Script Access

The store object is automatically available in all scripts. It operates on the current session's store (or an ephemeral store if no session header is present).

def run(req):
    # Shopping cart example
    cart_raw = store.get("cart")
    cart = json_parse(cart_raw) if cart_raw else []

    # Add item from request body
    new_item = req["body"].get("item")
    if new_item:
        cart.append(new_item)
        store.set("cart", json_stringify(cart))

    total = sum([item.get("price", 0) for item in cart])

    return {
        "cartItems": len(cart),
        "cartTotal": total
    }

Counter pattern

def run(req):
    # Track per-session request count using the counter builtin
    count = counter("request_count", 1)
    log("Session request #", count)

    return { "sessionRequests": count }
MethodDescription
store.get(key)Read value. Returns None if key doesn't exist.
store.set(key, value)Write a string value. Overwrites existing values.
store.delete(key)Remove a key from the session store.
store.keys()Return a list of all key names in the session store.

Managing via Admin API

Session management

# List all active sessions
curl http://localhost:8080/_api/sessions

# Response
{
  "sessions": [
    {
      "id": "user-alice-session-1",
      "createdAt": "2024-01-15T10:00:00Z",
      "lastActivityAt": "2024-01-15T10:05:00Z",
      "storeKeyCount": 3
    }
  ]
}

# Inspect a specific session's store
curl http://localhost:8080/_api/sessions/user-alice-session-1

# Invalidate (delete) a session
curl -X DELETE http://localhost:8080/_api/sessions/user-alice-session-1

# Invalidate all sessions
curl -X DELETE "http://localhost:8080/_api/sessions?confirm=true"

Admin UI

The Store page lets you create, edit, and delete global store entries with a key-value editor. The Sessions page shows all active sessions, their last activity time, and lets you inspect or delete individual sessions.

Session Expiry

Sessions are automatically cleaned up after a period of inactivity. Configure this in config.yaml:

session:
  headerName: "X-Virtual-Session-Id"   # Header name
  inactivityTimeout: "30m"             # Expire after 30 min of inactivity
  maxSessions: 10000                   # Max concurrent sessions

Valid duration units: s (seconds), m (minutes), h (hours). Example: "2h30m".

💡
Inactivity vs total lifetime The timeout is based on inactivity — each request with the session ID resets the timer. A session that receives regular traffic will never expire unless you explicitly delete it or restart the server with in-memory storage.

Use Cases & Examples

Stateful shopping cart

Multiple endpoints (add item, view cart, checkout) share session state:

## POST /cart/items — bound script
def run(req):
    cart = json_parse(store.get("cart") or "[]")
    item = req["body"]
    cart.append({"id": uuid(), "name": item["name"], "price": item["price"]})
    store.set("cart", json_stringify(cart))
    return {"count": len(cart)}

## GET /cart — bound script
def run(req):
    cart = json_parse(store.get("cart") or "[]")
    total = sum([i["price"] for i in cart])
    return {"items": cart, "total": total, "count": len(cart)}

Login flow simulation

## POST /auth/login — bound script
def run(req):
    email = req["body"].get("email", "")
    password = req["body"].get("password", "")

    # Simple mock auth check
    if email == "admin@example.com" and password == "secret":
        token = uuid()
        store.set("authenticated", "true")
        store.set("userEmail", email)
        store.set("authToken", token)
        return {"success": True, "token": token}
    else:
        store.set("authenticated", "false")
        return {"success": False}

## GET /me — bound script (checks auth)
def run(req):
    authenticated = store.get("authenticated") == "true"
    email = store.get("userEmail") or ""
    return {"authenticated": authenticated, "email": email}

Configurable feature flags

# Admin sets feature flags in global store
curl -X PUT http://localhost:8080/_api/store/features \
  -d '{"value": "{\"newCheckout\": true, \"betaSearch\": false}"}'

## Script reads feature flags (inherited from global store)
def run(req):
    features_raw = store.get("features") or "{}"
    features = json_parse(features_raw)
    return {
        "newCheckout": features.get("newCheckout", False),
        "betaSearch": features.get("betaSearch", False)
    }
